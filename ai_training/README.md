# AI Training Workspace Architecture Guide

Welcome to the **RM Monitor AI Training Workspace**. This isolated environment is dedicated exclusively to Machine Learning development, algorithm comparison, model training, evaluation, and versioned export.

---

## 1. Directory Structure

```
ai_training/
├── datasets/             # Data loading scripts & local dataset wrappers
├── preprocessing/        # Data scaling, encoding & missing value handlers
├── feature_engineering/  # Feature loaders & importance registry integration
├── training/             # Model training pipelines (Scikit-Learn, XGBoost, etc.)
├── evaluation/           # Evaluation metrics, confusion matrices, SHAP analysis
├── experiments/          # Experiment tracking & hyperparameter logs
├── notebooks/            # Jupyter/Colab exploratory notebooks
├── reports/              # Model performance summary reports & charts
├── models/               # Local staging folder for trained checkpoints
├── utils/                # Logging, file I/O & system helpers
└── config/               # System configurations, paths & hyperparameters
```

---

## 2. Dataset Integration Flow

The `ai_training` workspace never duplicates operational database records. It reads directly from the datasets generated by the RM Monitor application:

```
RM Monitor (MySQL)
    ↓
Dataset Generator (datasetGeneratorService.js)
    ↓
Data Cleaning Pipeline (dataCleaningPipelineService.js)
    ↓
Feature Engineering (featureEngineeringPipelineService.js)
    ↓
backend/ml_datasets/feature_dataset.csv
    ↓
ai_training/dataset_loader.py
```

---

## 3. Model Export Flow

Trained models are automatically versioned and exported into the main RM Monitor prediction engine directory:

```
ai_training/export_model.py
    ↓
ai/models/ (e.g. rm_model_v1.0.0.joblib)
    ↓
RM Monitor AI Prediction Engine
```
